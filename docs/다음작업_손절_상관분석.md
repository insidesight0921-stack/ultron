- 가격 원천 `_get_pykrx_price()` = pykrx OHLCV **최신 종가**(장중 실시간 아님).

### 근본 원인 (2중 지연)

→ 둘이 겹쳐 평균 -14.2%에서야 청산.

### 옵션 (결정 필요)

3. **갭/급락 즉시 청산 로직** or 단계·트레일링 손절.
4. **손절선(-7%) 재검토**: 데이터상 폭이 아니라 실행이 문제라 후순위.

## B. 손실 ↔ 거시국면 / 섹터 상관 분석

### 목표
6~7월 손실이 특정 **거시 국면**이나 **섹터**에 몰렸는지 정량화 → 회피/비중 규칙 후보 도출.

### 데이터 소스
- **거시 국면**: `quant_bot.snapshot(months).consensus_phase` ∈ {Recovery, Expansion, Slowdown, Contraction}.
  - 주의: snapshot은 *현재* 국면. 과거 월 국면은 (i) 해당 시점 기준 재계산 or (ii) 근사값 라벨링 필요(결정).
- **섹터**: 현재 종목→섹터 매핑 **없음**. 후보: pykrx 업종분류 vs 보유 종목 수동 맵(15종목 규모라 수동도 현실적).

### 설계 (순수 우선)
- `trade_analytics` 확장: `correlate_pnl_by(rts, label_fn) -> {label: {pnl, n, win_rate}}`.
  - `label_fn(roundtrip) -> 라벨`(국면 or 섹터)을 **주입**해 순수·테스트 가능.
- 리포트/LLM 총평에 "손실이 X 국면·Y 섹터에 N% 집중" 한 줄 추가.

### 파일 / 테스트
- `scripts/trade_analytics.py`(순수 상관 함수 + 포맷), 라우팅은 기존 `analysis` 토픽 재사용.
- 라벨 소스(phase_fn/sector_fn)만 주입식이면 hermetic 테스트 가능.

### 결정 질문
- 섹터 분류: pykrx 업종 vs 수동 맵? / 국면: 월별 재계산 vs 현재값 근사?
